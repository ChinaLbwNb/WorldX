# WorldX 技术总览

WorldX 的目标是把“一句话生成 AI 世界”做成完整闭环：用户输入一句自然语言描述，系统自动生成世界设定、地图、角色、交互规则，并启动一个由 AI 角色自主决策和演绎的模拟世界。

例如：

> 夜晚的宋朝繁华夜市，有当铺掌柜、算命先生、捕快、小偷、酒鬼，还有一个刚从现代穿越来的网红。

几分钟后，系统会生成一个宋朝夜市：角色会守店、巡逻、闲逛、观察彼此、对话、记忆并反思。后续故事没有预写剧本，而是由角色在运行时自主决定。

## 为什么做 WorldX

Stanford Generative Agents 证明了 AI 角色可以在一个固定小镇中自主生活、社交并产生涌现行为。之后的 AI Town、Microverse 等项目继续推进了这个方向，但它们普遍有一个限制：世界通常是预先搭好的，场景、角色、地图交互需要人工配置。

WorldX 试图把“创建世界”本身也自动化：

- 一句话描述生成世界设计。
- 自动生成地图、角色、交互区域和运行时配置。
- 自动启动 AI 角色模拟，让角色自主行动、对话、记忆和反思。

## 架构总览

WorldX 由四个核心模块组成：

| 模块 | 职责 | 主要模型 |
| --- | --- | --- |
| Orchestrator | 把一句话展开成结构化世界设计 | 强推理模型 |
| Generators | 生成地图、NPC、用户角色 spritesheet、标注和物品素材 | 绘图模型 + 视觉审查模型 |
| Server | 驱动角色决策、对话、记忆和持久化 | 高频、低成本语言模型 |
| Client | 渲染世界、播放事件、提供用户交互 | Phaser 3 + React |

贯穿全系统的核心契约是 `world-design.json`。它驱动初始世界的地图生成、区域定位、世界 NPC 生成、动作规则、运行时模拟和客户端展示，避免每个模块重新理解用户输入。账号用户角色是账号资产，后续从“我的角色”面板单独生成，不写入世界 NPC 配置。

## 世界生成管线

### 1. 世界设计

用户输入会先交给 Orchestrator。Orchestrator 负责生成结构化世界方案，包括：

- 世界主题、时代、风格和氛围。
- 地图描述和主活动区。
- 角色列表、职业、人设、外貌和初始目标。
- 可交互区域、可交互元素和世界动作。
- 角色在当前世界中能理解的外貌提示，例如古代角色不会看到“网红”这个现代概念，而会看到“衣着和镇上人格格不入的人”。

这些内容会写入 `world-design.json`，作为后续生成和运行时的单一数据源。

### 2. 地图生成

WorldX 没有采用固定 tile 素材拼装地图，而是让文生图模型直接生成完整背景图。为了让这条路可控，地图生成 prompt 会加入明确约束：

- 俯视或接近俯视视角。
- 静态纯背景，不包含角色。
- 道路和活动区需要连通。
- 主要路面不能被建筑、树木、墙体严重遮挡。
- 可进入建筑使用横切视角，便于在同一张地图上观察内部活动。

生成后会交给视觉模型审查。如果审查失败，系统会把反馈转为新的约束并追加到下一轮 prompt 中，形成“审查 -> 约束注入 -> 重试”的收敛循环。

### 3. 地图标注

地图必须从“好看的图片”变成“代码能理解的地图”。WorldX 的关键思路是：让图像模型直接在原图上用指定颜色涂抹可行走区域、区域和交互元素，再通过程序比较原图与标注图的色彩差异，得到精确坐标。

这一方案绕开了多模态模型不擅长直接输出精确坐标的问题：

- 模型擅长看出哪里能走、哪里不能走。
- 模型不擅长直接写出准确像素坐标。
- 让模型“画出答案”，再由固定代码计算坐标，可以获得更稳定的结果。

对可行走区域，系统会检测青色覆盖产生的像素差异，并把它转换为 tile 级 0/1 网格。判定时会综合强证据、弱证据、边缘噪声过滤和窄走廊抢救，避免角色走到墙上，也尽量保留一格宽通道。

对区域和可交互元素，系统使用多色彩标注。每批最多标注少量元素，减少颜色过多导致的不稳定，再通过颜色对应关系恢复元素身份和坐标。

### 4. 角色动画生成

角色不是单张立绘，而是可行走的分帧精灵图。WorldX 使用固定参考模板来约束四方向行走和待机动画的帧布局，再让图像编辑模型在模板基础上改绘目标角色。

这种方式比从零生成分帧图更稳定：

- 每帧位置、尺寸、间距可控。
- 多个角色的动画结构一致。
- 切图和播放逻辑更简单。

抠图使用边缘种子 BFS：只从图片边缘开始移除接近背景色的区域，避免误删角色衣物中与背景色相近但没有连接到边缘的部分。

## 运行时模拟

### Tick 循环

Server 以 Tick 作为模拟的最小时间单位。每个 Tick 内会执行：

1. 推进世界时间，必要时进入跨日流程。
2. 更新所有角色的被动状态，例如需求和情绪衰减。
3. 清理失效对话会话。
4. 找出可以决策的角色。
5. 并行执行角色感知、动作菜单构建和 LLM 决策。
6. 从 `talk_to` 意图中选择可成立的对话会话。
7. 执行非对话行动。
8. 并行执行对话。
9. 按周期触发微反思。
10. 异步调度记忆评估和事件归档。

角色处理顺序会随机打乱，避免固定顺序造成不公平优势。记忆评估异步执行，不阻塞下一轮 Tick。

### 感知、决策与执行

角色不是全知的。决策前会构建一份只包含当前角色应该感知到的信息：

- 当前所在区域和位置描述。
- 同区域其他角色及其可见行为。
- 明显情绪波动。
- 附近可交互对象。
- 最近世界事件。
- 自己近期行为摘要，用于避免重复行动。
- 与当前情境相关的记忆。

动作菜单由世界配置和当前上下文共同生成，角色只能在合理行动中选择，例如移动、互动、等待、与某人交谈、回应对话等。

### 记忆与反思

角色记忆包括观察、对话、经历、反思、传闻、梦境等类型。检索默认不依赖 embedding，而使用可解释的四维评分：

```text
score = relevance * 3 + recency * 2 + importance * 2 + emotionalIntensity
```

这种线性模型便于调试：如果角色总忘记重要事件，可以调高 importance；如果角色太沉浸于过去，可以调整 recency。

记忆生命周期包括：

- 衰减：随时间和使用频率变化。
- 淘汰：低衰减值且长期不用的记忆会淡化或删除。
- 巩固：高重要性或多次被检索的记忆会成为长期记忆。

反思分两级：

- 微反思：每隔一段模拟时间，从近期记忆中提炼洞察，可能影响情绪和当前关注点。
- 日终深度反思：跨日时回顾全天经历，生成更高层次反思，并强化相关旧记忆。

### 对话系统

对话从角色意图开始，而不是脚本触发。一个 Tick 内可能多个角色想聊天，系统会进行冲突消解：

- 每个角色同一 Tick 最多参与一个对话。
- 已有对话优先续接。
- 新对话按随机顺序配对。
- 被锚定的角色不能主动离开岗位，但其他角色可以前往找它。

对话中还支持内心独白。角色可能在表面客套时产生自己的真实想法，让观赏性更强。

### 情绪系统

情绪使用 Valence + Arousal 双维模型：

- Valence 表示正负情绪。
- Arousal 表示唤醒度或紧张程度。

组合后可以表达兴奋、焦虑、平静、低落等状态。情绪会随 Tick 自然回落，世界事件、交互结果和反思会造成偏移。只有当情绪波动足够明显时，其他角色才能感知到，避免每个角色都像“情绪透明人”。

## 用户干预与时间线

WorldX 提供“上帝模式”：

- 全局广播：向整个世界注入事件。
- 耳语或托梦：向单个角色注入私密信息。
- 人设编辑：运行时修改角色人格、动机或说话风格。
- 架空对话：把角色拉出来聊天，不影响世界进程。

同一个世界可以创建多条时间线。每条时间线独立持久化，便于比较不同干预是否会带来不同结局，也支持历史回放。

## 客户端架构

客户端采用 Phaser 3 + React 19 混合架构：

- Phaser 负责地图、角色 sprite、动画、相机和寻路。
- React 负责面板、表单、时间线、事件流、角色详情等 UI。
- 双方通过 EventBus 通信。

地图渲染采用非常规方式：视觉层直接展示 AI 生成的整张背景图，逻辑层读取 TMJ 中的碰撞网格、区域和交互对象。这样地图可以是任意视觉风格，游戏引擎只关心可行走性和坐标。

角色移动使用 EasyStar.js 做 A* 寻路，并加入路径平滑、墙边惩罚和寻路失败降级。极端情况下如果目标不可达，角色会先尽量移动，再通过淡入淡出传送到目标，避免卡死。

## 持久化

WorldX 使用 SQLite + 文件系统：

- 每条时间线一个独立 SQLite 数据库。
- 事件流、记忆、角色状态、世界状态、快照和 LLM 调用日志分别落表。
- 数据库使用 WAL 模式。
- 事件流同步写入 `events.jsonl`，供 Replay 模式使用。
- 日终快照通过 checkpoint WAL 后复制 SQLite 文件实现，简单但可靠。

## 与 Stanford Generative Agents 的差异

| 维度 | Stanford Generative Agents | WorldX |
| --- | --- | --- |
| 世界 | 手工搭建的固定小镇 | 一句话自动生成 |
| 地图 | 预制地图 | 多模态管线自动生成和标注 |
| 角色 | 预设固定角色 | AI 自动设计并生成外观动画 |
| 记忆检索 | Embedding 相似度 | 可解释的关键词和权重模型 |
| 自我修正 | 较少 | 审查、约束注入、重试循环 |
| 用户干预 | 有限 | 广播、耳语、人设编辑、架空对话 |
| 时间线 | 单线模拟 | 多时间线和历史回放 |

## 当前阶段与未来方向

项目当前处于 Alpha 阶段，核心能力可用，但仍有很多可继续探索的方向：

- 用户附身某个角色，直接参与世界。
- 世界走廊或社区，让用户分享和下载世界。
- 根据故事大纲自动演绎视觉小说。
- 多场景联动，让角色跨世界互动。
- 无限地图，角色接近边界时继续生成新区域。
- 抽离地图、NPC、用户角色和物品生成能力，辅助小型游戏开发。
- 引入 embedding 检索作为可选记忆检索方案。
