# Player UI Redesign

WorldX 的主界面目标是面向玩家，而不是面向编辑器。地图画面应占据完整视口，UI 作为游戏 HUD 覆盖在地图内部。

## 当前阶段

第一阶段已完成基础 HUD 化：

- 顶部横向工具栏不再占用布局高度。
- 左上角显示当前世界、时间和运行状态。
- 左上角世界卡片可展开世界/时间线管理。
- 地图内部上方显示运行/回放和开始/暂停。
- 右上角显示资源、账号入口和语言切换。
- 右下角提供 React 覆盖层可折叠玩家菜单，包含我的角色、背包、邀请玩家、事件日志、单人聊天、生成 NPC、地图、上帝模式和工具入口。
- HUD 图标使用 `client/public/ui/icons/*.png`，由 `GameIcon` 组件统一渲染。
- “生成 NPC”和“地图”已拆成两个独立入口：NPC 面板只负责当前地图 NPC 生成，地图面板只负责地图节点列表、传送和新地图生成。
- 从菜单或按钮打开的复杂功能窗统一收敛为屏幕中央的矩形窗口，避免不同面板继续在右侧、顶部和地图角落堆叠。
- 居中窗口使用浮动层级：新打开或被点击的窗口会自动提升到旧窗口上方。
- 生成类交互需要显示进度条和日志；地图/NPC 使用后端 job 日志，物品/用户角色当前使用前端阶段日志，后续可替换为真实 job API。

## UI 分层

当前采用轻量覆盖层方案：

- `TopBar`：临时承载 HUD 覆盖层，包括世界状态、资源、运行控制和右下角玩家菜单。
- React 面板：负责复杂表单、列表、账号、背包、角色、建造等重交互内容。
- Phaser 场景：继续负责地图、角色、采集按钮、物品摆放预览等地图内直接交互。

曾试过把右下角菜单迁入 Phaser 原生 `HudScene`，但运行时明显变卡，已回退。下一步若继续引擎 UI 化，应先做性能分析，不再直接新增常驻 HUD Scene。

## 布局原则

- 主地图全屏展示，HUD 不改变 Phaser 画布布局。
- 第一层只放玩家当下常用信息：世界、时间、资源、运行状态、玩家菜单。
- 编辑器感入口必须收进二级菜单，例如时间线管理、Dev 工具、观察/管理工具。
- 图标承担识别，文字只作为辅助标签。
- 小地图靠近左上角运行信息下方，缩放控件放在小地图下方；公屏聊天和右下角玩家菜单保持为常驻 HUD，不纳入居中弹窗规则。

## 下一阶段

- 将 `TopBar` 继续瘦身，保留世界/时间线选择和运行状态；右下角玩家菜单后续可拆成独立 React 组件。
- 把上下文动作（采集、对话、拾取、摆放）统一成底部中间的 `ContextActionBar`。
- 把创作/管理类入口收进“创作工坊”，不要直接暴露在主 HUD 第一层。
- 为移动端/窄窗口增加专门布局，避免左上、右上、顶部运行条互相挤压。
